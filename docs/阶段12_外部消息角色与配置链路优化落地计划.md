# 1. 阶段目标

## 1.1 建设目标

本阶段解决当前用户使用链路中两类核心问题：

1. **外部回调消息身份错误（方案 A）**：入站 Webhook 消息当前以 owner 用户身份（`sender_type="USER"`）落库，与真人消息无法区分，审计、短记忆、会话摘要全部记在 owner 头上。本阶段新增「外部来源」消息角色，让外部系统的消息有独立身份，并在前端可视化区分。
2. **配置链路繁琐（方案 B）**：从连接器到技能到智能体再到会话，横跨 5 个页面、15+ 次手工操作，版本-保存-发布三段式重复两遍。本阶段以「创建向导 + 一键保存并发布 + 引导链接」压缩操作步骤，降低跨页面跳转成本。

## 1.2 本阶段不做什么

- 不引入 Dify 式的完整 `ExternalUser` 实体表与按外部用户隔离会话（列为后续进阶迭代，本阶段只做消息角色与来源标记）。
- 不改动版本化数据模型本身（Skill/Agent 版本机制保留），只优化发布交互。
- 不重构会话页整体布局与样式体系（遵守项目记忆中的 macOS 视觉规范与 CSS 变量规则）。
- 不改动通用 Webhook 的验签、幂等、回写协议。

## 1.3 参考基线

- Dify：内部成员与外部用户身份分离，消息带 `from_source` + 终端用户标识。
- Coze：发布为单次动作（选渠道即发布），无需先建版本再绑定渠道。
- 项目现状关键代码：
  - 通用 Webhook 落库：`app/services/chat_application.py` L97（`sender_type="USER"`）
  - Webhook SecurityContext：`app/services/inbound_webhook.py` L552-L556
  - Message 模型：`app/models/message.py` L23（`sender_type`）
  - 技能创建/发布：`console/src/pages/Skills.tsx` L448-L548、L688-L739
  - 智能体版本/绑定/发布：`app/api/routes/agents.py` L106-L148
  - 连接器发现/注册：`console/src/pages/Connectors.tsx` L671-L693、L888-L947

# 2. 工作分解

## 里程碑 M12-1：外部消息角色（方案 A）

**状态：已实施（2026-11-20），迁移 a8c2e5d7b1f3，全量测试 598 passed**

### A-1 数据模型扩展

| 项 | 内容 |
| --- | --- |
| 改动 | `app/models/message.py`：`Message` 新增两个可空字段 `source`（String(32)）与 `external_sender`（String(128)） |
| 取值 | `source` ∈ `console` / `api` / `webhook` / `external`；`external_sender` 存外部发送者标识（外部系统 conversation_key、webhook 名 + key） |
| 迁移 | Alembic 新增一次迁移，两列均可空，存量数据不回填（视为 console 来源，逻辑兜底） |

**验收：** 迁移在 sqlite 与 postgres 均可执行；存量消息读取不受影响。

### A-2 后端落库链路改造

| 项 | 内容 |
| --- | --- |
| `handle_chat` | `app/services/chat_application.py`：签名新增可选 `source: str = "console"` 与 `external_sender: str | None`，写 USER 消息时带入 |
| 通用 Webhook | `app/services/inbound_webhook.py`：`_handle_chat` 调用处传 `source="webhook"`，`external_sender` 取 `config.name + conversation_key`；`event_part`（content_parts 内）保持现有元数据不变 |
| 触发校验 | `app/kernel/task/service.py` L109：触发消息查询由 `sender_type == "USER"` 放宽为 `IN ("USER", "EXTERNAL")` |
| 短记忆插件 | `app/builtin_plugins/short_memory.py` L51：拼接历史时保留 `EXTERNAL` 消息（当前逻辑为全量拼接，仅需确认不受影响并补充测试） |
| 事件总线 | `app/services/chat_event_bus.py`：`ChatMessageEvent` 增加 `source`/`external_sender` 字段并随事件透传 |

**验收：** 通过通用 Webhook 投递一条消息，落库后 `sender_type="EXTERNAL"`、`source` 与 `external_sender` 正确；任务正常触发、模型正常响应。

### A-3 前端渲染区分

| 项 | 内容 |
| --- | --- |
| 类型 | `console/src/types/index.ts`：消息类型补充 `source?` / `external_sender?` |
| 气泡 | `console/src/pages/Chat.tsx`：`EXTERNAL` 消息渲染独立样式（中性灰气泡 + 来源徽标，如「Webhook · xxx」）；真人用户蓝气泡、助手灰气泡维持现状 |
| 事件接入 | Chat.tsx L1206-L1248 SSE 接入处透传新字段 |

**验收：** 同一会话内真人消息与外部回调消息视觉可区分；`/embed/chat` 嵌入页不破坏。

## 里程碑 M12-4：会话页使用门槛（衔接项）

**状态：已实施（2026-11-20），迁移 f2c3d4e5a6b7，全量测试 608 passed**

实现说明：
- `Agent.is_default` 字段 + 租户级部分唯一索引 `uq_zr_agent_default`（写法同 is_default_parent）；`POST /agents/{id}/set-default` 同租户互斥（设置新默认清旧默认），归档时清除默认标记。
- 会话页 fallback：上次选中 > is_default > is_default_parent > 第一个；inbound_webhook 目标智能体来自配置项无 fallback 链，未改动。
- 会话页空态（无已发布智能体）在引导卡片下展示 4 步 checklist（连接器登记工具 → 创建并发布技能 → 创建智能体 → 发布版本），各步探测实际数据状态（tools/selectable total、skills 已发布数）并给深链。
- 智能体详情页已发布状态新增「设为默认」入口，列表与会话页选择器展示「默认」徽标。

| 项 | 内容 |
| --- | --- |
| 默认智能体 | `Agent` 模型新增 `is_default` 标记（参考现有 `is_default_parent`）；会话页未选智能体时使用默认项；Webhook 目标智能体由配置项指定，无 fallback 链 |
| 空态引导 | 会话页无已发布智能体时展示 checklist（连接器 → 技能 → 智能体 → 发布），每步检测实际数据状态并给深链（复用 B-5 的 URL 约定） |

**验收：** 新用户从零配置到会话页发消息，全程有引导且默认智能体自动就位。

# 3. 实施顺序与依赖

```
M12-1（消息角色）→ M12-2（一键发布）→ M12-3（链路串联）→ M12-4（会话门槛）
```

- M12-1 独立性最强、风险最低，先行落地；其中 A-2 触发校验放行必须与 A-1 迁移同一批次提交，避免中间态任务无法触发。
- M12-2 的 B-1（技能原子发布）是 B-4（技能向导）的前置。
- M12-4 依赖 M12-3 的 URL 约定，但默认智能体部分可提前并行。
