## 二、必须修正的事实性错误

**1（最关键）`execute_simulated` 仍然是假成功，v1.1 校正改错了方向**

- `task.result = {"mode": "simulated", "status": "completed"}`（[dispatcher.py](file:///D:/project/z-torque-community-m1/app/kernel/task/dispatcher.py#L166)）
- 一条 `[MOCK] task completed` 的 ASSISTANT 消息（[dispatcher.py](file:///D:/project/z-torque-community-m1/app/kernel/task/dispatcher.py#L168-L178)）

## 三、按现文档实现会返工的设计缺口

**1. `project` 维度没有实体（最高风险）**
全仓 `project_id` 0 命中，模型只有 Conversation / Message / Task。§2.2 的四维键 `(tenant, agent, project, user)` 落不了地——会变成永远为 NULL 的列，唯一约束也写不出来。**先定义 project 归属**（Conversation 增列？新建 Project 表？Agent 归属 project？），再定记忆键与迁移。

**2. FTS5 表设计缺三件事**
`zr_knowledge_fts` 只有 `chunk_id/text/source_path`：① 缺 tenant 维度，跨租户安全完全依赖每个查询都正确 join，一次漏写即泄漏；② 缺同步机制（external content + 触发器，或应用侧双写），否则索引陈旧且不可见；③ 缺删除级联——文件删除接口在 [files.py](file:///D:/project/z-torque-community-m1/app/api/routes/files.py#L173)、用户删除在 [admin_iam.py](file:///D:/project/z-torque-community-m1/app/api/routes/admin_iam.py#L342)，两者都必须触发索引与记忆清理，文档未提。

**3. 现有解析器产生不了引用坐标**
[file_parser.py](file:///D:/project/z-torque-community-m1/app/services/file_parser.py#L13-L50) 把 PDF 前 100 页、Excel 20 表×10000 行直接拼成纯文本并截断，页码/行号在拼接时已丢失。§2.1 的 `line_start/line_end/page_no` 无法从今天的结果生成；且 xlsx 需要 `sheet + row + col`，schema 只有 page/line 覆盖不了。**parser 升级是知识库的隐性前置依赖**，应单列一条并进 P0。

**4. Windows 兜底与"process 不可信"自相矛盾**
§2.3 第 5 条先声明 process 是可信开发态，又让 Windows 用 `process + 严格 scope` 对外兜底——这等于把"无 OS 隔离 + 有路径访问"设为默认。建议：无容器/WSL 时**直接拒绝不可信执行**（保持现在的 `AI_CAPABILITY_UNAVAILABLE`），scope 只作纵深防御。

**5. diff 写审计与 metadata-only 审计直接冲突**
§2.3 要 before/after diff 持久化到审计，§三-3 要求审计不存工具参数与结果。建议拆开：diff 存独立 artifact（TTL、脱敏、租户隔离），审计只记 `artifact_id + hash + 路径 + 大小`。

**6. PatchTransaction 的并发/TOCTOU/多文件原子性未定义**
`old_text` 校验到写入之间文件可能已变；多文件回滚本身失败时如何收敛未定；`O_NOFOLLOW` 只保护最后一级，父目录符号链接仍需 realpath；缺少文件锁与提交前 hash 复校验。§9.4 的 launcher 可信性约束同理。

**7. Scope 用 ContextVar 传递不可靠**
`asyncio.to_thread` 只单向复制上下文（线程内改动不回传），subprocess 完全不继承。§2.3 第 1 条写 ContextVar、第 2 条又写"调用参数增加 Scope"，二者取其一——**选显式不可变 Scope 参数进 Executor/SandboxDriver 接口**。

**8. lease 缺 fencing token，取消缺 ack**
只有 `lease_owner/expires_at` 时，过期恢复的旧持有者仍可能写终态；需要 `attempt_epoch` 并在终态写入前校验。取消除了"落库标志 + 抢占"，还需要 ack 与在途副作用对账（幂等键 + 执行日志），否则与正在跑的工具竞态。boot ledger、幂等 reply 存储也没有进入 §八 清单。

**9. 上下文治理缺两个前置决定**
pyproject 里没有任何 tokenizer，token 预算无从计算；cache key 只写 `(conversation_id, compaction_seq)`，但 z-torque 是多 provider/多模型，应含 model/provider；压缩摘要存哪张表、如何版本化、失败如何回退，正文与 §八 都没写。

**10. Postgres 部署下没有 FTS5**
alembic 里已有 `dialect.name != "sqlite"` 分支，说明非 SQLite 是被考虑的。§2.1/§八 只有 FTS5 方案，要么明确"知识检索仅 SQLite 部署可用"并在 capability 上报，要么给 Postgres `tsvector` 等价方案。

**11. 知识检索没有和 scope 绑定**
find/grep 类工具能读文件，但 §2.1 没写受 `allowed_paths`/tenant 约束，路径收口只出现在 §2.3——容易实现成"能 grep 整台机器"。

**12. 检索验收不可验证**
"未命中时模型无法编造来源"做不到。可验证的是：回答无引用被系统标记/拒绝、每条引用必须能在 chunk 表命中。需要一份 golden set（问题→期望文档/片段）才能验收命中率与引用准确率。
