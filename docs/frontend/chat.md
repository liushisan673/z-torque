
# Chat / 会话页 · 前端详细设计说明

## 1. 页面定位

- 面向用户的主交互入口。
- 完成：选 Agent → 对话 → 附件 → 普通回复 / Task 执行过程 → 结果与确认。
- Task 不单独做一级导航，执行过程集成在本页。
- 未选 Agent 时使用系统默认父 Agent。

**核心验收链路在本页完成：**  
登录后进入 Chat → 选 Agent → 发消息 → 看流式回复或 Task 过程 → 看结果。

---

## 2. 整体布局（建议三栏）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶栏：Logo / 当前用户 / 退出（可与全局布局共用）                            │
├──────────────┬─────────────────────────────────────┬─────────────────────┤
│              │                                     │                     │
│  左侧栏      │           中间主区                   │   右侧过程面板       │
│  会话列表    │      消息流 + 输入区                 │   （Task 执行过程）  │
│  + Agent选择 │                                     │   可折叠             │
│              │                                     │                     │
│  宽约 240–280│           弹性占满                   │   宽约 320–360      │
│              │                                     │   无 Task 时可收起   │
└──────────────┴─────────────────────────────────────┴─────────────────────┘
```

- 小屏：左侧会话列表可抽屉化；右侧过程面板可底部抽屉或覆盖层。
- 无进行中 Task 且无历史 Task 可看时，右侧可默认收起，扩大中间区。

## 3. 左侧栏：会话列表 + Agent 选择

### 3.1 Agent 选择区（顶部固定）

| 元素 | 说明 |
|------|------|
| 当前 Agent 展示 | 显示名称；未选择时显示「默认父 Agent」或文档约定的默认名称 |
| 下拉/选择器 | 列出当前用户有权使用的 Agent（官方 + 自己的） |
| 区分标识 | 官方 / 我的（标签或图标） |
| 版本信息 | 可选展示当前生效的 AgentVersion 简短标识 |
| 切换行为 | 切换 Agent 不自动清空当前会话，但新消息按新 Agent 处理；或按产品约定「新开会话再切」并给出提示 |

**空态：** 无可用 Agent 时提示「暂无可用智能体，请先在 Agent 页创建或复制」，并链到 Agent 页。

### 3.2 会话列表

| 元素 | 说明 |
|------|------|
| 新建会话按钮 | 明确「新建会话」；点击后创建空会话并选中 |
| 会话项 | 标题（首条用户消息摘要或用户命名）、最后一条时间、可选未读/进行中标记 |
| 进行中标记 | 该会话有未结束 Task 时显示状态点（运行中 / 等待确认） |
| 选中态 | 当前会话高亮 |
| 排序 | 默认按最近更新时间倒序 |
| 操作 | 重命名（可选）、删除（需确认）；删除仅自己的会话 |
| 分页/滚动 | 支持加载更多或虚拟滚动 |

**空态：** 「暂无会话，点击新建开始对话」。

**权限：** 只展示当前用户自己的会话（文档：私有会话按用户隔离）。

## 4. 中间主区：消息流 + 输入

### 4.1 顶部会话信息条（可选但建议有）

- 当前会话标题（可编辑）
- 当前 Agent 名称 + 版本
- 若有关联根 Task：简短状态（如「任务执行中」「等待确认」），点击可聚焦右侧面板

### 4.2 消息列表

按时间正序展示，支持滚动加载历史。

**消息类型与展示：**

| 类型 | 展示内容 |
|------|----------|
| 用户消息 | 文本；附件卡片（文件名、类型图标、大小、状态） |
| 助手普通回复 | 流式 Markdown/纯文本；流式过程中显示光标或「生成中」 |
| 系统/状态提示 | 如「已创建任务」「任务已取消」，样式弱于对话气泡 |
| 与 Task 关联的助手消息 | 可带「查看执行过程」入口，点击打开/聚焦右侧面板 |
| 错误消息 | 使用统一错误展示：优先 `code` 对应文案 + `message`，可展示 `trace_id`（可复制） |

**流式规则（文档硬性要求）：**

- 普通聊天与 Task 使用**两套**事件处理逻辑，不能混成一套。
- 普通聊天事件示例：`message.delta` / `message.result` / `message.done`
- 不得根据 `message` 文本做分支，应用 `code` 与 Task 状态判断错误。

**附件在消息中：**

- 已上传成功：可点击（若后端提供预览/下载且权限允许）
- 上传中 / 失败：明确状态，失败可重试或移除（针对未发送的）

### 4.3 底部输入区

| 元素 | 说明 |
|------|------|
| 文本输入框 | 多行，支持 Shift+Enter 换行、Enter 发送（可配置） |
| 附件按钮 | 选择文件；展示待发送附件列表（名称、大小、移除） |
| 发送按钮 | 发送中禁用，防止重复点击（文档要求） |
| 停止按钮 | 流式输出或 Task 进行中时可停止当前输出（调用后端取消/停止语义） |
| 字数/状态 | 可选；发送中显示 loading |

**附件约束（与文档一致）：**

- 支持类型：PDF、TXT、MD、CSV、XLSX、图片、音频  
- 默认上限 50MB（以后端配置为准）  
- 前端做类型与大小提示；最终以后端校验为准  
- 上传状态：选择中 → 上传中 → 成功/失败；失败可移除  

**发送前校验：**

- 无内容且无附件时禁用发送  
- 无可用 Agent 时提示并禁用或引导去配置

## 5. 右侧：Task 执行过程面板

### 5.1 何时出现

- 当前会话存在进行中的 Task，或用户主动点开某条与 Task 关联的消息  
- 可手动折叠/展开；有「等待确认」时应自动展开并高亮  

### 5.2 面板结构

```
┌─────────────────────────────┐
│ 任务标题 / 状态标签          │  如：运行中 | 等待确认 | 成功 | 失败 | 已取消
│ Agent 名称 · Version        │
│ 可选：根 Task ID（可复制）   │
├─────────────────────────────┤
│ 进度与阶段列表（时间线）      │
│  · 正在理解需求              │
│  · 正在执行某项能力          │
│  · 工具调用摘要              │
│  · 工具结果（成功/失败）      │
│  · 等待用户确认   [确认][拒绝]│
│  · 正在整理结果              │
│  · 最终结果 / 失败原因        │
├─────────────────────────────┤
│ 父子任务层级（若有委派）      │
├─────────────────────────────┤
│ 结果摘要区                   │
│ 错误与 Trace（若有）         │
└─────────────────────────────┘
```

### 5.3 阶段展示规则（对齐文档）

- 阶段文案是对服务端事件的解释，**不能虚构未发生的步骤**。  
- 映射真实事件，例如：  
  `task.snapshot` / `task.status` / `task.delta` / `task.tool_call` / `task.tool_result` /  
  `task.waiting_human` / `task.human_decision` / `task.result` / `task.error` / `task.done`  
- 工具参数与返回值只展示后端脱敏、裁剪后的摘要。

### 5.4 人工确认

当状态为等待确认时：

| 元素 | 说明 |
|------|------|
| 说明文案 | 后端下发的确认原因/摘要 |
| 确认按钮 | 调用确认接口 |
| 拒绝按钮 | 调用拒绝接口 |
| 取消任务 | 若允许，提供取消；取消父 Task 需展示取消传播语义（文档要求） |

确认/拒绝进行中按钮禁用，防止重复提交。

### 5.5 父子任务（单层委派）

若存在委派（文档：单层父子，子 Task 不再套子 Task）：

- 展示：父 Task → 子 Agent 名称 + AgentVersion + 子任务状态 + 进度 + 结果摘要 + 必要错误  
- 串行委派：能看出顺序、前置完成情况、等待原因、结果是否已回传父任务  
- 用户只能看到有权查看的摘要，不默认展示完整原始数据与子 Agent 中间推理  

### 5.6 断线与恢复

- SSE/流断开：不直接把 Task 标为失败  
- 重连后按事件序号 + 服务端状态恢复  
- 页面刷新：先拉 Task 当前状态，再决定是否重连流  
- 已结束的 Task 停止监听

## 6. 状态与空态、加载、错误

| 场景 | 展示 |
|------|------|
| 首次进入无会话 | 左侧空态 + 中间引导「选择 Agent 并新建会话」 |
| 会话无消息 | 中间欢迎语 + 输入区可用 |
| 历史加载中 | 消息区顶部 loading |
| 发送中 | 输入禁用，发送按钮 loading |
| 流式中 | 助手气泡持续更新 |
| 403/无权限 | 明确无权限提示，不静默失败 |
| 401 | 跳转登录 |
| 业务错误 | 展示统一结构：`message` + 可选 `trace_id`，用 `code` 做逻辑分支 |
| 网络错误 | 可重试提示 |

## 7. 权限在本页的体现

| 能力 | 无权限时 |
|------|----------|
| 使用 Chat（发消息） | 输入区禁用 + 提示 |
| 查看自己的会话 | 列表为空或提示 |
| 取消自己的 Task | 不显示取消或禁用并说明 |
| 人工确认 | 仅自己发起的 Task 可操作 |

前端显隐只改善体验，**以后端 PEP 为准**。

## 8. 关键交互流程（实现时按此串）

### 8.1 新建并发送第一条消息

1. 用户选 Agent（或使用默认）  
2. 点「新建会话」→ 调用创建会话 API → 左侧选中新会话  
3. 输入文本，可选上传附件（先上传拿到附件引用再发送）  
4. 点发送 → 请求带上 `conversation_id`、Agent/Version、内容、附件引用  
5. 若返回普通流：中间区走 Chat Stream  
6. 若返回 `task_id`：打开右侧面板，改走 Task Stream  

### 8.2 继续已有会话

1. 左侧点选会话 → 加载历史消息  
2. 若有未结束 Task，拉取状态并按需重连 Task Stream  
3. 发送逻辑同 8.1  

### 8.3 停止 / 取消

- 停止生成：停止当前流式展示，并通知后端取消生成（若接口支持）  
- 取消 Task：调用取消接口；若为父 Task，界面提示取消会传播到子任务  

---

## 9. 本页明确不做的内容

- 不做可视化 Workflow 编排  
- 不在前端执行 Skill/脚本/Tool  
- 不直连数据库或模型  
- 不把 Task 做成一级导航页  
- 不解析 `message` 文本做错误分支  
- 不持久化模型密钥或 Connector 凭证

- [ ] 刷新或断线后能恢复 Task 状态，不误判失败  
- [ ] 错误展示含可理解提示与 trace_id（如有）  
- [ ] 无权限与未登录行为符合规范
