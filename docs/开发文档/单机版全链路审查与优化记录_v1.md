# Z-Torque 单机版全链路审查与优化记录（v1）

> 目标：以 Windows 单机版 `.exe` 为最终交付形态；主应用数据库优先使用 SQLite；不依赖用户自行安装 PostgreSQL、Redis、Docker 或其他服务即可启动社区版核心功能。
>
> 范围：本文件记录当前代码审查结果和本分支的改造边界。未完成项不视为已支持；性能目标不冒充实测数据。

## 1. 当前执行链路总览

```text
Windows EXE / Local API
  ├─ SQLite + Alembic
  ├─ Auth / SecurityContext / AIP
  ├─ Conversation / ContextBuilder / Memory
  ├─ ModelSelector / ModelGateway
  ├─ ExecutionLoop
  │    ├─ SkillGateway → HTTP / DB_QUERY / MD-Skill / MCP
  │    ├─ in-site A2A → child Agent → same TaskRuntime
  │    ├─ Confirmation / Checkpoint / Resume
  │    └─ TaskEvent / Outbox / Recovery
  ├─ FileStore → Parser → KnowledgeProvider (FTS5 / LIKE)
  ├─ Connector lifecycle → MCP stdio / Streamable HTTP / REST
  └─ Local Console assets
```

## 2. 链路审查结论

| 链路 | 当前实现 | 本轮发现/改进 | 仍需完成 |
|---|---|---|---|
| 主数据库 | SQLAlchemy + Alembic；SQLite 可运行，PostgreSQL 仍作为开发/CI 方言 | WAL 初始化、busy timeout、外键、NORMAL synchronous、WAL checkpoint；补 PRAGMA 测试 | 单机数据目录、备份/恢复、并发写压测、打包后迁移验证 |
| 文件解析 | TXT/MD、CSV、PDF、XLSX | 改为惰性生成，按 chunk 上限消费；避免 XLSX 全量单元格先入内存 | 大文件压测、解析错误可恢复、上传/索引后台化 |
| 知识库 | SQLite FTS5 BM25；FTS5 不可用时 LIKE 降级 | 批量 chunk/FTS 写入；权限路径在 SQL Top-K 前过滤；增加中文 CJK 片段补召回；文档/消息双源配额 | 当前仍是词法检索，不是向量语义检索；需建立真实中文/英文评测集，评估是否引入可选远程 Embedding |
| Memory | SQLite 持久化三级作用域；短期/长期/工作记忆 | 限制每作用域注入条数和总字符数；无 conversation_id 时不返回会话记忆 | 记忆质量评估、过期/合并策略、长会话压力测试 |
| Context | 最近消息、摘要、附件检索、上下文修复与压缩 | 当前有 token/字符预算和工作记忆缓存 | 检查缓存失效与长记忆更新的一致性；测量 prompt 构建耗时和 token |
| ModelGateway | OpenAI-compatible，支持普通/流式/工具调用 | HTTP 错误不重试；仅对响应格式解析失败有限重试 | 请求耗时/首 token/总 token 可观测性；供应商响应大小与流式断连测试 |
| TaskRuntime | 本地队列、Task 状态机、Outbox、TaskEvent、Checkpoint | 修复进程重启时 RUNNING 任务盲目重放的风险：有工具/检查点活动则标记恢复状态不确定，不自动重复外部副作用 | SQLite 多任务写冲突压测；更完整的阶段级恢复/人工核对流程 |
| A2A | 默认 Supervisor 调用站内子 Agent | 单一结构化 Router、当前发布版本、可见性校验、每次执行最多一次派发、结构化失败结果 | 固定路由评测集；记录候选/选中/耗时/最终任务质量 |
| MCP | stdio + Streamable HTTP，JSON-RPC，session lifecycle | HTTP 响应流式限长；stdio 行长度限制、并发读写串行化、关闭时清理进程树 | 真实 MCP Server 兼容性矩阵、取消/断线恢复、DNS/IP 与私网策略测试 |
| REST Connector | HttpExecutor，目标主机校验与 DNS pinning | 响应体读取阶段限长；默认不重试非幂等 POST | 真实服务契约测试、连接池/重试/限流评估 |
| DB Connector | DB_QUERY 受控 SELECT 与表/列授权 | 仍需检查查询行数上限、语句超时、CTE/SELECT * 等 AST 边界 | 补 SQL 安全回归和 SQLite/PG 方言测试 |
| Sandbox | POSIX process/container；Windows 按能力降级 | Windows 不应被描述为强隔离；不可信脚本在 Windows 必须 fail-closed | EXE 下 Python 子运行时路径；Windows 进程树/文件系统/网络边界验证 |
| Frontend | Console 已有任务、知识库、Agent、Connector 页面 | 本轮不改 UI，避免后端契约未稳定时返工 | 后端链路稳定后统一优化状态、错误、耗时和调试可见性 |
| EXE Packaging | 当前仓库没有完整的可交付 EXE 启动链 | 本分支新增单机启动器与 PyInstaller 构建基础（后续提交） | Windows CI 构建、启动/迁移/登录/停止 smoke test，签名与升级策略 |

## 3. 已确认的单机版原则

1. 主应用数据库默认 SQLite；不要求用户安装独立数据库服务。
2. SQLite 仍通过 SQLAlchemy + Alembic 管理，不在业务层散布 SQLite 专属 SQL（FTS5 插件是明确的本地实现边界）。
3. 数据库、用户上传文件、密钥和日志必须放在用户可写的数据目录，不写入 EXE 所在目录或 PyInstaller 临时解压目录。
4. 只读程序资源（Console dist、Alembic migration、默认 Skill）与用户可变数据分离。
5. 单机版仍保留 Tenant/User/SecurityContext 的权限边界；“单机”不等于取消 AIP、审计或确认机制。
6. MCP/REST 等外部连接是可选能力；无配置时不阻塞应用启动。
7. Windows 进程模式不是安全沙箱。只有显式可信、经过确认的脚本才允许执行；不可信脚本必须拒绝，不能以普通子进程冒充隔离。
8. 前端优化放在后端契约、任务事件和链路指标稳定之后。

## 4. 本轮性能/准确率优化原则

- **少做无效工作**：批量 DB 写入；按需生成解析块；在 Top-K 前做权限过滤；限制 Memory/Connector 响应大小。
- **不牺牲业务安全换速度**：非幂等 POST 不自动重试；工具执行中断不盲目自动重放；A2A 不允许模型任意多派发。
- **可比较而非凭感觉**：记录模型轮次、工具耗时、A2A 选中结果、知识检索来源与命中；后续建立固定评测集。
- **SQLite 作为真实目标环境**：Windows + SQLite 全量测试必须通过；PostgreSQL 测试用于保护方言抽象，不作为单机版启动依赖。

## 5. 后续实施顺序

### A. SQLite 与 EXE 基础
- 单机数据目录与首次启动配置/密钥初始化。
- Alembic 启动迁移、管理员初始化、Console 静态资源定位。
- PyInstaller Windows 构建与 smoke test。
- 文件备份、恢复、异常退出后 WAL/数据库完整性检查。

### B. 核心链路正确性
- Task 恢复和幂等边界。
- Sandbox Windows 降级行为与脚本运行时。
- MCP/REST/DB Connector 的超时、大小限制、取消和错误传播。
- Knowledge/Memory 权限隔离与召回评测。

### C. 性能与评测
- SQLite 并发写入与长任务压测。
- 文件解析、知识索引、检索延迟基准。
- ModelGateway 首 token/总耗时、Token 使用。
- A2A 路由准确率、误调用率、重复调用率。
- 50 条起步的固定场景集；达到稳定后扩展至 100 条。

### D. Frontend
- 统一任务状态、工具调用、审批等待、失败/中断/恢复展示。
- 展示可解释的执行时间线和链路耗时。
- 知识库检索来源、文件坐标和降级状态。
- Connector 连通性、权限、错误原因与响应时间。
- 最后再统一视觉和交互，不提前重构页面。

## 6. 测试说明

本文件不宣称任何尚未运行的测试已通过。每一批代码提交后以 GitHub Actions 的 Windows + SQLite、Ubuntu + SQLite、静态检查和前端构建结果为准。EXE 交付前必须增加独立的 Windows 打包/启动工作流。
