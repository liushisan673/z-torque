## 2. 根因（3 条）

1. **概念平铺**：必需（会话/智能体）、可选（技能/连接器）、平台设置（模型/Webhook/用户/审计）三类东西，等权排在同一个顶栏 8 个入口。
2. **工程概念外泄**：版本、草稿、发布、版本快照、Secret URI 直接摆给用户。
3. **没有设计系统**：无单一令牌源，每页各造一套 → UI 优化只能修修补补。

## 3. UI 方案：antd 6 + Ant Design X，视觉语言对齐 DSH

### 3.1 为什么是这条路线

1. **零新增依赖**：`antd 6.7.1` + `@ant-design/x 2.10.0` 已装。而 X 的组件正好对应会话页手写的东西：

   | X 组件 | 替换 |
   | --- | --- |
   | `Bubble` | `.chat-msg-bubble`（用户/AI/外部来源三态） |
   | `Sender` | `.chat-composer`（输入 + 附件 + 发送/停止） |
   | `Conversations` | `.chat-session-list` |
   | `Prompts` | 空态建议词 |
   | `Think` / `ThoughtChain` | `.chat-run-*` 执行过程块（CSS L2374-L2552） |
   | `Attachments` | `.chat-attachment-card` / `.chat-pending-file` |

   → 会话页 1580 行 CSS 预计 **可删 1000+ 行**。

2. **补齐真正缺的能力**：`Table`、`Form`（校验）、`Steps`（向导）、`Result`/`Empty`、`Drawer`、`Descriptions`、`Upload`。
3. **主题一处切换**：`ConfigProvider` + `darkAlgorithm` 替代 150 个手工变量与逐页暗色覆盖。

### 3.2 DSH 设计语言（从安装包 `app.asar` 提取的真实令牌）

DSH 用**三层令牌**（调色板 → 语义别名 → 组件），这是它"简洁"的机制来源：

```
--dsw-static-*      调色板（neutral-bluish 00…1000、blue、green、red、amber）
      ↓
--dsw-alias-*       语义（bg-base / bg-layer-1..3 / border-l1..l4 / label-primary..tertiary / state-*）
      ↓
--dsw-elevation-*   --dsw-font-*    --dsw-radius-*    组件层
```

**核心调色板（实测值）**

| 角色 | 值 |
| --- | --- |
| 中性偏冷灰阶 | `#fff` `#f9fafb` `#f5f6f7` `#f1f3f5` `#ebeef2` `#e1e5ee` `#cfd3d6` `#adb2b8` `#979da6` `#81858c` `#61666b` `#353638` `#2c2c2e` `#232324` `#1b1b1c` `#151517` `#0f1115` |
| 主蓝 | `#3b82f6`(500) `#2563eb`(600) `#1e40af`(800) |
| 状态 | success `#22c55e` / warning `#f59e0b` / error `#ec1313` |
| 暗色底 | `#151517` → 层叠 `#232324` / `#2c2c2e` |

**四条"气质规则"（比颜色更重要）**

1. **描边用发丝线，不用灰实线**：`border-l1/l2/l3` = `#0000000a` / `#0000001a` / `#0000001f`（4% / 10% / 12% 黑），`outline` 按钮是 **0.5px** 描边。
2. **阴影几乎看不见，只托层次**：`elevation-soft` = `0 0 0 .5px stroke, 0 4px 16px #00000008, 0 0 24px #00000008`（3% 透明双层）。
3. **主色只出现在"动作"上**：界面本体是近黑文字（`#0f1115`）+ 白底，蓝色只给主按钮/链接/选中态。这正是它显得克制的原因。
4. **连续圆角**：`--dsw-corner-shape: superellipse(1.5)`（苹果式 squircle，非普通圆角），胶囊另有 `corner-shape: round`。

**控件几何（实测）**：按钮 `md` 高 36 / 字号 14 / 行高 22 / 横向 14；`sm` 高 28 / 字号 12 / 行高 18 / 横向 10；控件间距 4；禁用透明度 0.4；Pill 高 24 / 字号 12 / 圆角 999；过渡 **0.2s**。

| DSH 令牌 | 值 | antd `theme.token` |
| --- | --- | --- |
| `bg-base` / `bg-layer-1` | `#fff` / `#f9fafb` | `colorBgContainer` / `colorBgLayout` |
| `bg-layer-2` | `#f5f6f7` | `colorFillQuaternary` |
| `bg-layer-3`（暗） | `#2c2c2e` | `colorBgElevated`（dark） |
| `label-primary` | `#0f1115` | `colorText` |
| `label-secondary` | `#61666b` | `colorTextSecondary` |
| `label-tertiary` | `#81858c` | `colorTextTertiary` |
| `brand-primary` | `#2563eb` | `colorPrimary` |
| `button-primary-hover` | `#3b82f6` | `colorPrimaryHover` |
| `border-l1` / `l2` / `l3` | `#0000000a` / `1a` / `1f` | `colorBorderSecondary` / `colorBorder` / `colorSplit` |
| `state-success` / `error` / `warn` | `#22c55e` / `#ec1313` / `#f59e0b` | `colorSuccess` / `colorError` / `colorWarning` |
| `elevation-soft` | 见上 | `boxShadow` / `boxShadowSecondary` |
| `radius-md` / `sm` | 8 / 6 | `borderRadius` / `borderRadiusSM` |
| `controlHeight` md / sm | 36 / 28 | `controlHeight` / `controlHeightSM` |
| `font-family` | `-apple-system, BlinkMacSystemFont, …` | `fontFamily` |
| `transition-duration` | 0.2s | `motionDurationMid` |
| 暗色底 | `#151517` | `colorBgBase` + `theme.darkAlgorithm` |

**与现状的差异（即"变简洁"的具体来源）**：

| 维度 | 现在 | 改后 |
| --- | --- | --- |
| 主色 | `#3455db` 偏紫蓝，且技能页 `#007aff` | 统一 `#2563eb`，删除 `#007aff` |
| 描边 | `#e5e8ee` 灰实线 1px | 4%/10%/12% 黑发丝线，部分 0.5px |
| 阴影 | `0 4px 16px rgba(16,24,40,.08)` 单层 | 发丝线 + 3% 双层 |
| 暗色底 | `#12151c` 偏蓝 | `#151517` 中性近黑 |
| 字号 | 13、13.5、14、15、18、20、26、30 混用 | 14 / 12 两档 + 标题 20 |
| 圆角 | 6/8/12/14/999 混用 | 6/8/12 + 胶囊 999 |

> 注：`corner-shape: superellipse()` 是较新的 CSS 特性（Chromium 139+）。Z-Torque 是浏览器访问，需按渐进增强处理：支持则启用，不支持回落 `border-radius`，不阻塞。

## 4. 使用流程方案（按决策 2 重写）

### 4.1 目标

> **新用户登录后 60 秒内发出第一条消息**：1 个页面、1 张表单、约 6 个输入项。

（原目标"0 步"随模型兜底删除而作废——这是你要求的取舍：模型必须显式配置。）

### 4.2 前置：删除全局模型兜底（后端）

要让"必须先配模型"成立，需移除以下**隐式回落**，让缺失模型变成显式错误：

| 位置 | 现状 | 改后 |
| --- | --- | --- |
| `app/api/routes/chat.py` L74 | `... or getattr(gateway, "default_model", "mock")` | 无模型 → 抛 `AI_MODEL_NOT_CONFIGURED` |
| `app/services/chat_application.py` L129 | 同上 | 同上 |
| `app/kernel/ports/model_selector.py` L54-L80 | `resolve_model_selection` 回落 `default_model` | 回落分支删除，改为必填校验 |
| `app/builtin_plugins/model_gateway.py` L386、L455 | `default_model` 属性兜底 | 删除兜底语义 |
| `app/builtin_plugins/plugins.py` L90-L104 | 用 `settings.model_*` 组装全局网关 | 改为「按已配置的模型资源解析」 |
| `app/builtin_plugins/model_selector.py` L7 | 注释里的"默认回退"策略 | 同步更新 |
| `app/kernel/task/runtime.py` L210、`app/services/execution_loop.py` L220 | 传 `default_model=settings.model_name` | 改为必填解析 |

**配套的两处闸门**：

1. **智能体发布预检 —— 保持软提醒（按决策 5）**：现状"未绑定模型"是警告、可「仍要发布」强制跳过（`Agents.tsx` L707-L712、L1701-L1723）。**不改为硬阻断**，只优化弹窗措辞：把"对话将无法调用大模型"改为"发布后可保存，但在绑定模型前**无法开始对话**"，并给出「去绑定模型」直达按钮。
2. **会话发起 —— 新增友好兜底**：无模型时返回明确错误码 `AI_MODEL_NOT_CONFIGURED`，前端渲染引导卡片（"这个智能体还没绑定模型 → 去绑定"），而不是抛原始错误或白屏。这是决策 5 的配套：既然允许发布未绑模型的智能体，就必须在真正"用"的那一刻给出可执行出路。

**保留**：`mock` 网关只在测试里通过依赖注入使用，不再由 `settings.model_name` 隐式生效。

> 影响面提醒：这会改动对话主链路与任务执行链路，需同步跑全量测试（当前基线 **608 passed**）。

### 4.3 L0′：一步开通（新用户唯一必做步骤）

```
登录
 └─ 探测 /system → model.configured == false 且无模型资源
     └─ 进入「开通向导」单屏表单：
          ① 选择厂商预设（DeepSeek / OpenAI / 通义 / 自建…）
          ② 粘贴 API Key
          ③（可选）选择或填写模型标识 model_id
          ④ 给助手起个名字（默认「我的助手」）
        ↓ 一次提交（单事务）
        后端：Secret 加密存储 + 模型资源 + 「我的助手」智能体（已发布、绑定该模型）+ 默认会话
        ↓
     落在 /chat，输入框可直接打字
```

- **用户只需理解 2 个概念**：厂商、API Key。`供应商/接入点/Secret URI/版本/发布` 全部不出现在这一屏。
- 成本：1 个后端编排接口（幂等）+ 1 个前端向导页。
- 若部署方已在 `.env` 配好**且已建立模型资源** → 直接进会话，不必走向导。

### 4.4 L1：主线收窄（信息架构）

顶栏 8 项等权 → 3 组分级：

```
工作台           会话 · 智能体          ← 普通用户全部所需
能力扩展（可选）  技能 · 连接器          ← 顶部固定一句话："不配置也能对话，这里只是加能力"
平台设置（管理员） 模型 · Webhook · 审计 · 用户
```

普通用户视角只剩 **2 个**入口。

### 4.5 L2：对话内补齐 + 决策 4 的落地

**决策 4 已在后端实现**（`app/security/permissions.py` L49-L52）：

```
可见性 = 本人创建的资源 | 官方(OFFICIAL) | 管理员创建的平台资源
写保护 = 仅 owner 可改；官方/平台资源对普通用户只读（可"复制到我的"）
```

即"普通用户创建并发布 → 只有自己可见"**当前已是默认行为**，前端也已有「我的 / 平台」标签体系（`Agents.tsx` L36-L38）。**无需后端改动**，只需：

| 项 | 改动 |
| --- | --- |
| 文案纠偏 | 会话页现在写着"也可以联系管理员为你发布一个智能体"（`Chat.tsx` L1409、L1587）→ 改为"你也可以自己创建一个，仅自己可见" |
| 空态出口 | 会话页空态按钮从"去创建智能体"改为直达**开通向导/新建智能体**（1 次点击） |
| 来源提示 | 智能体选择器与详情区明确标注「我的（仅你可见）」与「平台（全员可用）」 |

**L2 能力卡片**（输入框上方，就地完成，不跳页）：

| 触发 | 卡片 | 交互 |
| --- | --- | --- |
| 想换模型 | 「换成我的模型」 | 复用 §4.3 表单 |
| 想查内部数据 | 「连接一个系统」 | 填 MCP 地址/选 REST 模板 → 自动发现 → 一键打包成技能并绑定当前智能体 |
| 想让它按规矩说话 | 「设定角色」 | 一句话系统提示词 → 保存即生效（内部升版本，对用户不可见） |

### 4.6 步骤对比

| 场景 | 现在 | 改后 | 减少 |
| --- | --- | --- | --- |
| 首次可用（必做一次） | ~20 步 / 5 页 | **1 屏 / 约 6 个输入项 / ≈60 秒** | ~85% |

### 9.1e 已完成（Sprint 1 · 第 5 批：执行过程实时可见 + 端到端延迟优化）

**问题 1（执行中黑屏）**：用户发起需求后，页面只显示到「开始执行」，之后**直到任务结束才一次性出现全部执行步骤**。

**根因**（实测代码路径）：worker 的整个执行体共用**一个事务**（`_execute_model_task`），而 `append_task_event` 只 `db.add` + `flush`，**不提交**；`/tasks/{id}/stream` 是另一个会话轮询 `zr_task_event`，因此只能看到 `_claim()` 那次 commit 之前的事件（`TASK_CREATED`/`TASK_STARTED`），工具调用/结果事件全被压在 worker 事务里，直到 `_finish_chat_task` 收尾 commit 才一起可见。

| 修复 | 落点 | 说明 |
| --- | --- | --- |
| 过程事件即时提交 | `app/services/execution_loop.py` `_progress_event()` | 每条工具调用/返回、每轮「模型推理中」写完立刻 commit；过程事件不参与状态机判断，提前提交不破坏不变量 |
| 新增「模型推理中」步骤 | 同上 | 每轮 `generate` 前落 `TASK_MODEL_STARTED`（带 round），用户能看见"正在等模型"而不是空白；推理完成不再单独发事件（紧随的工具/终态事件即结束标志） |
| SSE 轮询提速 | `app/services/task_stream.py` | 1.0s → **0.3s**，步骤上屏延迟从最多 1s 降到 0.3s |
| 首字节等待提示 | `Chat.tsx` + `index.css` | 结论为空时不再渲染空白气泡，改为 `spinner + 正在理解你的需求… + 已等待 Ns`（执行中改文案「正在执行…」）；运行中折叠行显示「执行过程 · N 步 · Ns」 |
| 内联块实时计时 | `chatRun.tsx` `useElapsed()` | 每秒刷新「已进行 Ns」，能区分"在跑"与"卡住"（借鉴 DSH 执行行） |

**问题 2（整体太慢）**：带 MCP 工具的智能体从发消息到看见最终内容明显偏慢。

| 优化 | 落点 | 依据与收益 |
| --- | --- | --- |
| **消除重复决策轮** | `execution_loop.serialize_seed/seed_round` + `checkpoints.create_seed_checkpoint/take_seed_checkpoint` + `stream_service` + `chat_application.create_chat_task(seed=)` + `runtime._execute_model_task` | `/chat/stream` 已经用同一份消息 + 同一组工具跑完一轮并拿到 `tool_calls`，worker 原来**从头再推理一遍**（同一轮模型调用付两次、等两次）。现在这一轮结论随任务落库为「种子」，worker 认领即取走并删除，直接执行工具、从第 2 轮继续；种子可用性严格校验（工具名必须仍在映射里），不匹配就退化为原路径 |
| MCP 会话复用 | `app/kernel/skill_gateway.py` | 原来**每次工具调用**都新建连接器并重新 `initialize`（远端 MCP 每个 RTT 200~500ms，一轮 3~4 个工具就是 1~2 秒）。改为按「端点 + 身份头 + 凭证指纹」缓存已协商会话（空闲 90s 关闭、上限 32、跨事件循环自动失效、失败即逐出），同一轮里第 2 个工具起省掉握手 |
| 结论打字机按长度自适应 | `Chat.tsx` / `ChatEmbed.tsx` | 原来固定「2 字/16ms」= 125 字/秒：1500 字回答要播 12 秒，任务早就跑完，用户还在等动画。改为整段约 1.1s 播完，超 4000 字直接整段上屏 |

**验证**：新增 `tests/unit/test_chat_seed_and_progress.py`（种子可用性校验、种子一次性消费、种子命中时**模型只推理一轮**且工具事件在**独立会话**立即可见）；后端全量 **619 passed / 24 skipped / 退出码 0**（基线 616 + 3 条新用例）。

### 9.1f 已修复（第 4/5 批的两处回归，浏览器实测复现 + 修复）
