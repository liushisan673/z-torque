# Z-Torque 控制台 UI 与使用流程优化方案

**文档编号：** ZT-COMMUNITY-P13
**文档版本：** v1.0（待评审，未实施）
**范围：** `console/` 前端全部 8 个页面 + `/embed/chat` 嵌入页
**状态：** 仅分析与方案，不含任何代码改动

---

## 0. 一页结论

| 问题 | 表面现象 | 真实根因 | 解法一句话 |
| --- | --- | --- | --- |
| ① UI 需要优化 | "样式不好看" | 6978 行手写 CSS、每页各一套规范、双主色双字体、依赖里躺着 0 引用的 antd 6 | **收口到一套设计令牌 + 成熟组件库**，不再逐页手工美化 |
| ② 使用繁琐 | "要先配 4 样东西才能聊" | 把 3 类东西（必需/可选/平台设置）平铺在同一个顶栏，且把"版本、发布、Secret URI"这些工程概念直接摆给用户 | **首次使用压成 0 步**，技能/连接器降级为"可选增强" |

两个问题是同一个病：**没有设计系统，也没有信息分级**。
建议路线：**Ant Design 6 + Ant Design X（依赖已装，零新增）+ 开箱即用预置 + 对话内补齐配置**。

### 1.2 UI 的 6 个具体毛病（都带证据）

1. **双主色冲突**：全局 `--primary: #3455db`，技能页单独定义 `--skill-accent: #007aff`。
   → 会话页的主按钮和技能页的主按钮**不是同一个蓝**，同一个人在两页之间切换会觉得"这不是一个产品"。
   （`index.css` L8 vs L174）

2. **双字体**：`--font`（系统字体栈）与 `--skill-font`（`SF Pro` 苹果字体栈）并存。
   → 技能页字体和别页不一致。

3. **手写 CSS 没有回归保护，已经出现真实 Bug**：
   `.btn-secondary` 悬停时 `background: var(--bg)`（近白）但文字仍是 `#fff` → **白底白字，按钮文字消失**。
   而这个类是「Secret URI 转换」按钮在用的（`SecretRefInput.tsx` L54）。
   同时 `.btn-secondary` 的默认样式和 `.btn-primary` 重复定义（都是一样的蓝底），说明这个类是复制粘贴产生的。
   （`index.css` L386-L403）

4. **死代码已经出现**：`.chat-setup-checklist` 等 8 条规则还在 CSS 里，但对应 JSX（M12-4 的 4 步配置清单）**已从 `Chat.tsx` 删除**。
   → 证明"改一处漏一处"靠人眼维护，不可持续。

5. **视觉语言是三份设计稿拼的**：`docs/frontend/` 下确实并存 `chat.html`、`skill.html`、`skill-mac.html` 三套稿，代码分别对齐。
   → 圆角有 8/12/14/999 四种，focus 环有 3 种写法，暗色主题靠逐页覆盖变量。

6. **缺基础体验件**：无骨架屏（只有 spinner）、无 Tooltip/Popover（用 `title` 属性）、响应式只有一个断点（登录页）。

### 1.3 使用流程现状：管理员首次跑通要多久

假设一个全新部署、只想"让它回答我一个问题"：

| 步 | 页面 | 操作 | 需要理解的新概念 |
| --- | --- | --- | --- |
| 1 | 登录 | 输账号密码 | — |
| 2 | 模型管理（登录后落地页） | 新建**供应商**：名称/类型/Base URL | 供应商 |
| 3 | 模型管理 | 生成 **Secret URI**（粘贴明文 → 点转换） | Secret URI / 密钥引用 |
| 4 | 模型管理 | 新建**模型**：显示名 + model_id | model_id |
| 5 | 模型管理 | 新建**接入点**：名称/Base URL/优先级 | 接入点 |
| 6 | 连接器管理 | 新建连接器 → 测试连通 | Connector |
| 7 | 连接器管理 | 发现工具 → 勾选 → 批量登记 | Tool |
| 8 | 技能管理 | 新建技能（含首版本） | Skill / 版本 |
| 9 | 技能管理 | 绑定工具 → **保存并发布** | 草稿 vs 发布 |
| 10 | 技能管理 | 管理员**首次启用确认** | 审批闸门 |
| 11 | 智能体管理 | 新建 → 写系统提示词 → 选模型 → 勾技能 | Agent / 版本快照 |
| 12 | 智能体管理 | **创建并发布** | 发布 |
| 13 | 会话 | 选智能体 → 新建会话 → 输入 → 发送 | — |

**合计：5 个页面、约 20 次交互、3 次"发布"、8 个工程概念。**

### 1.4 一个被忽略的关键事实（这条决定了方案能做多轻）

后端**本来就有全局模型兜底**：

- `settings.model_base_url / model_api_key / model_name`（`app/config.py` L127-L129）
- 智能体未绑定模型时，`model_selector` 回落到 `settings.model_name`
  （`app/kernel/ports/model_selector.py` L54-L80、`app/builtin_plugins/model_selector.py` L7）
- `/system` 接口已经暴露 `model.configured` 布尔值（`app/main.py` L258）

→ **只要部署时 `.env` 配好模型，用户在控制台一个模型都不用配也能正常对话。**
当前流程把"可选"当"必需"讲，是自己给自己设的门槛。这为"0 步上线"提供了现成能力。

## 2. 根因归纳（3 条）

1. **概念平铺**：必需（会话/智能体）、可选（技能/连接器）、平台设置（模型/Webhook/用户/审计）三类东西**等权排在同一个顶栏 8 个入口里**。用户看到 8 个平级按钮，无法判断从哪开始。
2. **工程概念外泄**：版本、草稿、发布、版本快照、Secret URI、租户 —— 这些是研发概念，被直接放进了用户任务流。
3. **没有设计系统**：没有单一令牌来源，每页各造一套变量和组件 → UI 优化只能"修修补补"，永远收不了口。

## 3. UI 优化方案

### 3.1 三条成熟路线对比

| 路线 | 代表 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- | --- |
| **A. Ant Design 6 + Ant Design X** | 阿里系，中文企业后台事实标准（2025-11 发布 v6） | 数据表/表单/弹窗/向导开箱即用；**本项目依赖已装**；中文语境；token 一处换肤 | 默认视觉"像 antd"，需 token 调出品牌感 | ✅ **推荐** |
| B. shadcn/ui + Tailwind v4 | 2026 后台新宠，代码归自己 | 主题灵活、体积小、AI 友好 | 8 个页面全量重写；表格/表单校验/国际化要自建（TanStack Table + RHF + zod） | ❌ 本次不做 |
| C. 继续手写 CSS，只做美化 | 现状 | 改动最小 | 6978 行继续膨胀；无障碍/暗色/响应式全靠人工 | ❌ 不解决根因 |

行业依据：Ant Design 在「企业 CRUD / 50+ 数据表」场景最强，shadcn/ui 强在「拥有代码 / 强定制 / 体积」，但代价是表格与表单生态要自建。
参考：[shadcn vs Ant Design vs MUI 2026 对比](https://unfoldcms.com/blog/shadcn-vs-ant-design-vs-material-ui)、[Ant Design X 官方文档](https://x.ant.design/components/introduce)

### 3.2 为什么选 A（三个硬理由）

1. **零新增依赖**：`antd 6.7.1` + `@ant-design/x 2.10.0` 已在 `package.json` 里躺着。
   而 `@ant-design/x` 提供的组件正好是会话页手写的那些东西：

   | X 组件 | 替换掉的手写实现 |
   | --- | --- |
   | `Bubble` | `.chat-msg-bubble`（用户/AI/外部来源三态气泡） |
   | `Sender` | `.chat-composer`（输入区 + 附件 + 发送/停止） |
   | `Conversations` | `.chat-session-list`（会话列表 + 更多操作） |
   | `Prompts` | `.chat-welcome` 里的空态建议 |
   | `Think` / `ThoughtChain` | `.chat-run-*` 执行过程块（2374-2552 行） |
   | `Attachments` | `.chat-attachment-card` / `.chat-pending-file` |

   → 会话页 1580 行 CSS 里，预计 **1000+ 行可直接删除**。

2. **补齐 8 个页面真正缺的东西**：`Table`（审计/用户/Webhook/工具/版本列表）、`Form`（模型/连接器/智能体表单校验）、`Steps`（向导）、`Result`/`Empty`（空态）、`Drawer`、`Descriptions`、`Upload`、`Tree`。

3. **主题一处切换**：`ConfigProvider` + `theme.darkAlgorithm` 替代 150 个手工变量和逐页暗色覆盖。

> 保留意见：antd 的"企业后台感"确实明显。做法是**只换零件、不换气质**——用 token 定品牌色、圆角、阴影，保留现有 `GuideCallout`（原因+出路）这类"有观点"的组件语义，不让界面变成通用模板脸。

### 3.3 三层落地结构

```
L1 令牌层   design token（色/圆角/间距/字号/阴影）→ theme.ts → <ConfigProvider>
            删掉全部 --agent-* / --skill-* / --model-* 页前缀变量，只留 3-5 个品牌级变量

L2 组件层   antd 为底 + 薄封装：AppModal / AppTable / AppForm / StatusTag / PageHeader / GuideCallout
            业务代码只依赖封装层；现有语义（二次确认要输名称、中文错误文案）作为封装参数保留

L3 页面层   按 P0 → P2 逐页迁移，迁一页删一页 CSS（禁止双份并存）
```

### 3.4 改造清单

**P0（收益最大，先做）**

| 项 | 内容 | 预期收益 |
| --- | --- | --- |
| 会话页 → `@ant-design/x` | Bubble / Sender / Conversations / Prompts / Think / Attachments | 删 1000+ 行 CSS，交互态（流式、停止、重发、复制）开箱可用 |
| 弹窗统一 | 29 处 Modal + 19 处 ConfirmDialog → `Modal`/`Drawer` + 一个 `AppConfirm` | 焦点管理、Esc、滚动锁、可访问性统一 |
| 表格统一 | 10 处手写 table → `Table`（含分页/空态/骨架/列宽） | 审计/用户/Webhook/版本列表一次性规范 |
| 品牌统一 | 二选一：保留 `#3455db` 作主色，删掉 `#007aff` 覆写；字体合并为一条栈 | 消除"两套主色两套字体" |

**P1**

| 项 | 内容 |
| --- | --- |
| 表单统一 | `Form` + `rules`：字段级错误、必填星号、帮助文案（现在靠手写 label+hint） |
| 空态统一 | `GuideCallout` → `Empty`/`Result` 封装，强制"原因 + 出路 + 深链"三段式，文案模板化 |
| 顶栏/导航 | `Layout` + `Menu`，支持分组（见 4.3） |
| 暗色 | `darkAlgorithm` 替代 20+ 条手动变量映射 |

**P2**

| 项 | 内容 |
| --- | --- |
| 加载态 | `Skeleton` 替代裸 spinner（列表页首屏） |
| 浮层 | `Tooltip` / `Popover` 替代 `title` 属性 |
| 表格增强 | 列设置、密度、导出（审计页） |
| 响应式 | 补断点（现在只有登录页有 `@media`） |

### 3.5 视觉规范（一次定死，写进 token）

| 维度 | 规定 |
| --- | --- |
| 栅格 | 8px 基准（4/8/12/16/24/32） |
| 圆角 | 4 档：4（小控件）/ 6（按钮输入）/ 8（卡片）/ 12（弹窗） |
| 字号 | 2 档：正文 14，标题 18–20（沿用现有 skill 页"两档字号"的思路，推广到全站） |
| 字重 | 3 档：400 / 500 / 600 |
| 阴影 | 3 档：`--shadow-sm` / `--shadow` / 弹窗投影 |
| 状态色 | 只用语义色（success/warning/error/info），**禁止**再新增 `--xxx-tag-*` 每页专属色 |

**预期结果**：CSS 从 **6978 行 → 目标 < 2000 行**（仅剩品牌定制和少量布局），CSS 变量从 **≈150 → < 20**。

## 4. 使用流程优化方案

### 4.1 目标（北极星指标）

> **新用户登录后 30 秒内发出第一条消息，跳页次数 0。**

现状：约 20 次交互 / 5 个页面 / 十几分钟。

### 4.2 三层策略

#### L0 开箱即用（解决 80% 用户，后端小改动）

- 部署/租户初始化时：若 `model.configured == true`，自动创建一个 **「通用助手」** 智能体
  （默认系统提示词 + 全局模型 + 无技能 + 已发布 + `is_default`），并落到默认会话。
- 用户登录直接进 `/chat`，**输入框可直接打字**，顶栏显示当前智能体"通用助手"。
- 成本：1 个启动钩子 + 1 条幂等 seed 数据；**不给用户新增任何概念**。
- 兜底：若 `model.configured == false`，不假装可用，改为展示"连一个大模型"卡片（见 L2）。

#### L1 主线收窄（解决"不知道从哪开始"）

顶栏从 **8 项等权** → **3 组分级**：

```
工作台         会话 · 智能体
能力扩展（可选） 技能 · 连接器        ← 默认收起为二级入口
平台设置（管理员）模型 · Webhook · 审计 · 用户
```

- 普通用户视角只剩 **2 个**入口（会话、智能体）。
- 技能/连接器页顶部固定一句话：**"不配置也能对话；这里只是给它加能力。"**

#### L2 对话内补齐（解决"想加能力不知道去哪"）

在会话页输入框上方做**能力卡片**，检测到缺依赖时就地出现、就地完成，**不跳页**：

| 触发 | 卡片 | 交互 |
| --- | --- | --- |
| 无模型 / 想换模型 | 「换成我的模型」 | 选厂商预设（DeepSeek/OpenAI/…）→ 填 API Key → 保存；后端自动建供应商+模型+接入点+密钥引用 |
| 想查内部数据 | 「连接一个系统」 | 填 MCP 地址或选 REST 模板 → 自动发现 → 一键"打包成技能并绑定当前智能体" → 回到对话 |
| 想让它按规矩说话 | 「设定角色」 | 一句话填系统提示词 → 保存即生效（自动升版本，对用户不可见） |

关键：把 **连接器 → 工具 → 技能 → 发布** 这条 4 步链，折叠成 **1 张卡片 1 次确认**。
（需要后端加一个编排接口：`discover → register → create skill → publish → bind agent`）

### 4.3 首屏改造对比

**现在**（空态死胡同：只有一个按钮跳到智能体页，4 步清单的 JSX 已被删，只剩死 CSS）

```
┌ 侧栏 ────────────┬ 主区 ────────────────────────────────┐
│ 智能体 [请选择 ▾] │        ⚠ 还没有可用智能体              │
│                  │   会话需要基于一个智能体才能开始        │
│ 会话             │   请先创建智能体，完成配置后发布版本     │
│  + 新建（禁用）   │        [ 去创建智能体 ]                │
│  暂无会话         │   也可以联系管理员为你发布一个智能体     │
└──────────────────┴──────────────────────────────────────┘
```

**之后**（首屏就是输入框，缺什么就在框上方补什么）

```
┌ 工作台 ▸ 会话 ───────────────────────────────────────────┐
│  通用助手 ▾                           [ 换模型 ] [ 加能力 ]│
├──────────────────────────────────────────────────────────┤
│                                                          │
│   你好，我是通用助手。可以直接问，也可以让我：            │
│   ① 查内部系统数据   ② 按模板写文档   ③ 定时汇总          │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 给通用助手发消息…                            [ ➤ ]  │  │
│  └────────────────────────────────────────────────────┘  │
│  💡 想用你自己的模型？[ 1 分钟配置 ]（可选，不影响现在使用）│
└──────────────────────────────────────────────────────────┘
```

### 4.4 步骤对比

| 用户场景 | 现在 | 之后 | 减少 |
| --- | --- | --- | --- |
| 只想聊天 | ~20 步 / 5 页 | **0 步**（登录即可） | 100% |
| 换成自己的模型 | 4 步（供应商→密钥→模型→接入点） | **1 个表单 2 个字段**（厂商预设 + API Key） | 75% |
| 接入内部系统/知识 | 5 页 / 12 步 / 3 次发布 | **1 张卡片 2 次确认** | ~85% |
| 新建专用助手 | 1 页（M12-2 已优化） | 1 页 + 3 个模板选 1 | 持平，但认知成本降低 |

### 4.5 四个关键设计决策（需要你拍板）

| # | 决策 | 说明 | 影响 |
| --- | --- | --- | --- |
| 1 | **"发布"对普通用户隐身** | 内部仍版本化，UI 只说"保存并生效"；管理员可开"高级模式"看版本 | 这是流程能压到 0 步的前提 |
| 2 | **版本号从主界面移除** | 挪到"历史版本"抽屉；列表不再显示 `v3`、`当前发布` | 减少工程概念外泄 |
| 3 | **Secret URI 不暴露给用户** | 用户只填 API Key，后端直接产出引用 | 消除"粘贴明文→点转换"这一步 |
| 4 | **模型三级合并** | 供应商/接入点/模型 → 一个"添加模型"表单，高级字段（base_url、优先级）折叠 | 4 步 → 2 字段 |

## 5. 分期计划

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| antd 视觉同质化，丢掉现在 macOS 质感 | 用 token 定品牌色/圆角/阴影；只替换零件不替换气质；保留 `GuideCallout` 这类有观点的组件语义 |
| 一次性迁移回归风险大 | 按页迁移，每页迁完即删对应 CSS（禁止双份并存）；沿用现有浏览器走查清单 |
| 预置智能体"假装可用"掩盖配置问题 | 预置前校验 `model.configured`；为 false 时降级为引导卡片，不生成假智能体 |
| L2 卡片依赖后端编排接口 | 一期可先做"跳页 + URL 预填"（`?bindTool=` / `?bindSkill=` 机制已存在），编排接口二期 |
| 隐藏"发布"让管理员困惑 | 按角色区分：普通用户隐藏，管理员保留"高级/版本"入口 |

---

## 7. 明确不做什么

- ❌ 不引入 Tailwind / shadcn（与 antd 并存会让样式治理更乱，且需全量重写）
- ❌ 不改后端版本化数据模型（Skill/Agent 版本机制保留，只改交互与种子数据）
- ❌ 不做第三套主题皮肤、不做多语言
- ❌ 不在本次方案内重写嵌入页 `/embed/chat`（它有独立的宿主约束，单独评估）
