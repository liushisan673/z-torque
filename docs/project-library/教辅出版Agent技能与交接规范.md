# 教辅出版 Agent / Skill 配置与交接规范

> 本文件是社区版本地业务配置的实施基线。Agent、Skill、知识库绑定数据保存在用户本机 SQLite 中，不属于 Git 仓库文件；本次提交提供新增 MD-Skill 角色模板与可扫描脚本，不会覆盖用户已经配置的 7 个 Agent、10 个业务 Skill 或 17 个知识库。

## 1. 项目开工参数

所有 Agent 共用以下项目参数，不得把“初中物理 / 人教版 / 某一地区”硬编码为默认值：

- 学科、学段/年级、地区/省份
- 课标版本、教材版本、册次
- 目标读者、产品形态、目标页码、开本
- 资料版本、截止日期、交付物格式
- 当前稿件版本、初录版本、校次/审次

参数缺失时先提问；每个交付物必须回写参数快照。

## 2. 角色职责

| 角色 | 主要职责 | 必须输入 | 核心交付 |
|---|---|---|---|
| 物理教辅总编/Router | 任务拆解、派单、汇总、版本与交接管理 | 项目参数 | 项目任务单、阶段状态、总编审定意见 |
| 教研分析师 | 课标、教材、真题/模拟题考情分析 | 课标原文、教材、真题、模拟题 | 课标映射表、考情报告、知识点频次表 |
| 教材研读员 | 指定版本教材研读 | 指定版本教材 | 章节知识图谱、实验/公式/易错点表 |
| 竞品研究员 | 竞品内容与产品分析 | 竞品样书/可核验资料 | 竞品对照表、证据来源 |
| 调研员 | 实地/电话/网络调研 | 调研目标、样本范围 | 调研方案、原始记录、结论与局限 |
| 内容编辑/命题 | 体例、组稿、命题、答案解析 | 考情报告、教材、体例 | 目录、双向细目表、稿件、答案解析、查重报告 |
| 录排制作员 | 方正录排、图片重绘、初录校样交付 | 已确认稿件、版式规范 | 初录 PDF、源文件、图片重绘清单 |
| 校对员 | 三校文字/数字/符号/格式 | 初录 PDF + 对应稿件版本 | 差错清单与轮次记录 |
| 责任编辑 | 三审内容、课标、结构、出版规范 | 独立稿件版本与证据 | 审读评分表、打回/通过建议 |
| 通读员 | 跨章一致性检查 | 完整合版稿 | 术语/编号/引用一致性报告 |
| 质检印务员 | 清样、印前、印制参数检查 | PDF 清样、印制参数 | 质检报告、待人工核验项 |
| 产品运营 | 卖点、培训、产品资料 | 确认版目录、样章、产品信息 | 卖点证据表、培训讲稿/课件内容 |
| 售后 | 产品使用与政策答疑 | 售后政策、产品资料 | 有依据的答复与升级记录 |

社群/政策/师资日常运营暂不纳入当前社区版业务范围。

## 3. 知识库绑定建议

按职责最小必要绑定，避免所有 Agent 都拿到全部资料：

- 教研分析师：教材、真题汇编、模拟题/练习试题精选、知识集锦、课标原文、复习课件。
- 教材研读员：对应学科/版本/学段的教材、教案、导学案和课件。
- 竞品研究员：竞品样书、竞品目录/定价/卖点资料；无竞品库时只能输出调研计划。
- 内容编辑/命题：教材、真题汇编、模拟题、知识集锦、考情报告、已确认体例。
- 校对员：初录 PDF、对应原稿、教材、知识集锦、真题/模拟题及答案基准。
- 责任编辑：课标原文、教材、体例规范、流程细则、稿件和校对问题清单。
- 质检印务员：流程细则、版式/印制规范、初录 PDF/清样、教材与真题基准。
- 产品运营：确认版目录、样章、产品定位、卖点证据、培训资料。
- 售后：售后政策、产品说明、勘误公告、版本信息；不得空库运行“检索知识库”规则。

流程细则文档《教辅图书出版行业工作流程及细则》必须入库并绑定给总编、录排、校对、责任编辑和质检印务角色。

## 4. 必须分离的审批

- 校对员只提交差错与“建议打回/建议通过”，不具备最终审批权。
- 责任编辑独立审读，输出评分和“建议打回/建议通过”。
- 任何正式进入下一阶段的“通过”、正式退回修改，都必须由人工确认；确认人不得是任务发起人。
- 审批必须挂在 Task Checkpoint 上，保留确认人、时间、意见、稿件版本、校次/审次。不得把执行前的脚本审批误认为审稿结论审批。

## 5. 统一交接物结构

每次 Agent 委派必须包含：

```json
{
  "project": {
    "subject": "", "grade_band": "", "region": "",
    "curriculum_version": "", "textbook_version": "",
    "target_pages": 0, "edition": ""
  },
  "input_versions": [],
  "deliverable_type": "",
  "summary": "",
  "evidence": [],
  "issues": [],
  "unresolved_questions": [],
  "artifacts": [],
  "recommended_next_stage": ""
}
```

差错项固定字段：类型、位置、原文、建议、严重度、轮次、证据来源、处理状态。

## 6. 硬计算与人工边界

- 可由脚本计算：题目记录频次、页码预算加总、字符数/差错率、规范化精确重复、文本版本差异。
- 必须基于结构化输入：每道题需有题目 ID、年份、地区、题型、知识点、分值等字段；未结构化资料不能宣称完整频次统计。
- 仍需专业印前软件/人工核验：PDF 色值、图片分辨率、拼版、折手、书脊、物理印张和最终下印。
- “万分之一”必须明确统计口径和字符数来源，不能用模型估计。

## 7. 本次新增的 MD-Skill

扫描后会创建草稿，需检查、发布并绑定到相应 Agent：

- `book-publishing-workflow`：流程总控与项目参数。
- `curriculum-standards-analysis`：独立课标分析。
- `field-research`：实地/电话/网络调研。
- `typesetting-production`：录排制作与初录交付规范。
- `proofreader`：独立校对角色。
- `responsible-editor-review`：独立责任编辑审读。
- `book-publishing-deterministic-checks`：确定性统计、预算、差错率和文本差异脚本。

脚本技能执行仍遵循现有 Task 人工审批、沙箱、Windows trusted 声明和权限边界。MD-Skill 被扫描为草稿不等于已发布或已绑定。
